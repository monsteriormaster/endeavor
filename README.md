# Endeavor

> 一款回合制养成 RPG —— 个人独立开发，Godot 4 + 全数据驱动架构。

架空世界，近似第一次工业革命的伦敦。玩家以家族管家的视角管理一个家庭：安排成员的行动、处理街面上的事件、在对话里做出选择，看着这个家一点点撑下去或者散掉。

游戏本体可运行，已导出 Windows 版本。本文档说明代码结构与设计思路。

## 核心设计

### 1. 全数据驱动的规则体系

游戏的剧情、角色、物品、触发规则全部外置为 JSON 配置，程序只负责解释规则：

```
resoures/
├── characters.json      角色属性与标签
├── trigger.json         触发器（条件 + 效果 + 展示内容）
├── items/               道具、装备、杂项，按类别分文件
├── plot/                剧情脚本，按角色/章节拆分
└── map/                 地图点位与场景说明
```

新增一段剧情或一件道具不需要碰代码，改表即可。这是整个项目的第一原则——**内容生产与引擎逻辑彻底解耦**。

### 2. 卡牌拖拽式触发器系统

玩法核心：把人物卡、道具卡拖进触发器的卡槽，满足条件后执行。

- **9 宫格卡槽布局**，槽位可声明接受的卡类型与标签
- **条件求值引擎**：按标签（tags / lack_tags）、数值阈值（属性 + bonus 对照区间）、执行者身份三类条件筛选可选分支
- **特异性加权排序**：多条分支同时命中时，按条件匹配度打分决定优先级（`卡牌情况` 按组规模 ×10，`any_slot` / `performer` 各分支 +20，`placed_count` +30，同分按声明顺序）
- **置灰反馈**：前置未满足时按钮禁用并给出原因，而不是静默失败

### 3. 剧情导入管线

剧本从结构化数据批量解析为对话节点、立绘、音效与效果指令，替代逐条手工配置。单条剧情从数分钟的重复劳动压缩为一次导入。

### 4. 判定数值模型

判定采用「属性骰 + 修正值」对照区间阈值（6-8 / 9+ 分档）的方式。

设计每个难度档时，用属性期望值反推该档所需的最低投入，而不是凭手感定数。早期版本曾出现主线因多骰档成功率过低而卡死的情况，通过计算各档的通过概率分布定位到问题档位并调整。

### 5. 静态审计

改版后最容易出的问题不是崩溃，而是**引用断链**：剧情指向了不存在的物品、触发器指向了已改名的角色、卡面引用了被删的图。

为此写了 Python 审计脚本，对全量配置做静态校验——资源引用完整性、触发器可达性、物品断链检测，共 352 项。每次改完跑一条命令，把人工点检换成回归测试。

## 项目结构

```
├── components/      UI 组件（对话、卡牌、触发弹窗、角色面板）
├── script/          系统脚本（玩家、存档、效果处理、剧情导入、触发器加载）
├── scene/           场景
├── map/             主城地图
├── resoures/        全部 JSON 配置与剧情脚本
├── art/             图像素材（角色立绘、UI、图标、背景）
├── audio/           音频（未纳入仓库，见下方说明）
├── theme/           主题、字体、九宫格样式
└── project.godot
```

## 运行

1. 安装 [Godot 4.7](https://godotengine.org/)（GL Compatibility 渲染后端）
2. 用 Godot 打开本目录的 `project.godot`
3. F5 运行

首次打开时 Godot 会自动重建 `.godot/` 导入缓存，需要一点时间。
