## 二、我的判断：**「藏品匣里的标本卡」—— 暗卡身 + 金工三线 + 独立铭牌**

### 为什么是暗的（四条理由）

1. **卡的内容本身是暗的**。道具那批是深底厚涂；立绘也是暗调。卡身若再用浅米纸，道具就变成"贴在纸上的一块深色方块"—— 这个问题**现在就存在**。
2. **`trigger.png` 就是胡桃木 + 深蓝毡 + 金**。暗卡身和游戏自己的招牌道具同族。
3. **明亮留给容器**。顶栏/货架/弹窗全是浅米羊皮纸，卡是**放在浅托盘上的深色藏品** —— 层次立刻出来，真实 TCG（炉石）就是这么做的。
4. **切图 PNG 的背景是透明的** → 暗卡身能把透明区**直接吃掉**，立绘/道具读作"被装裱"；浅卡身则读作"贴上去的"。**见 `卡面实装预览_AB.png` 左二 vs 右二（蓝宝石项链）**。

### ⚠️ 与既有决策的冲突（主动摊开）

2026-09-26 你说过「**抄色泽明亮的二次元游戏**」。暗卡和这条有落差。
**我的解释**：那条是指 **UI 容器**（顶栏/货架/弹窗确实全亮），**卡做深是为了与容器形成对比**、拿回"实物"感。
**这条必须你拍板** —— 所以我把保守选项 B 一起画了。

### 与已否掉的四样都不冲突

| 你否过的 | 这版怎么避开 |
|---|---|
| 「脏脏的不好看」（水渍/霉斑） | 全平涂，零纹理 |
| 「太像纸了，没有卡牌的质感」 | 材质是**硬质板**：顶左亮边 + 底右暗边做出厚度；语言是**金工**（三线 + 菱形），不是纸纹 |
| 「这都成相框了」 | **满版图像区 + 独立铭牌** —— 卡面被切成「窗 / 铭牌」两个区，符合四款真实参考的共同点（没有一款是"厚边框+一个空槽"） |
| 「不要图生图 / 原卡框没有优点」 | 纯文生图；**完全不复用旧 `card.png` 的任何构图** |

## 三、重写后的提示词（要点）

**区别于前几版的关键改动**：
1. **结构写成编号清单**（1) 卡身 2) 三线 3) 四角菱形 4) 空窗 5) 分隔线 6) 铭牌 7) 厚度）—— 上一版按段落写，模型会漏掉分带。
2. 明确 **`SOLID MOULDED CARD with real thickness, NOT paper and NOT a picture frame`**。
3. 明确 **铭牌占底部 30%** 并且**比卡身亮一档**（这是"卡"与"相框"的分界：相框没有铭牌）。
4. 明确 **分隔线中央一个菱形**（给名字区一个"上边界"）。
5. 否定句加满：`NO paper texture, NO parchment, NO water stains, NO foxing, NO torn/deckled edges, NO fibre, NO wood grain, NO noise, NO gradient, NO glow`；`NOT a picture frame, NOT a border floating on paper, NOT an ornate baroque frame, NOT acanthus scrollwork, NOT gold filigree`。
6. 明确 **"wide empty margins on all four sides"** 以便去水印。

## 二、素材在白底上会不会糊？——量化，别目测

先目测说「可疑的信、被诅咒的古董、银之钥 在白底上糊掉」；**量化把这句话否了，而且方向相反**。

对全部 22 个素材（1 立绘 + 21 道具）统计**不透明像素的平均亮度 L**，再算各候选卡身的对比度（`_best_ground.py`）：

| 候选卡身 | **最差素材对比** | 平均对比 | 最差的那个素材 |
|---|---|---|---|
| **白 255** | **86.3** | **157.1** | 可疑的信 |
| 骨 231（现 B） | 62.3 | 133.1 | 可疑的信 |
| 浅暖 200 | 31.3 | 102.1 | 可疑的信 |
| 中亮 160 | 8.7 | 62.9 | 可疑的信 |
| 暗 55（实测） | 5.9 | 47.9 | 骑士盔甲 |
| 中调 128 | 1.0 | 37.1 | 被诅咒的古董 |
| **暗 74（现 A）** | **0.8** | 34.5 | 精心磨制的小刀 |

- 素材亮度是**双峰**的：暗（骑士盔甲 60.5 / 物种起源 63.1 / 章鱼尾 64.5）、浅（可疑的信 168.8 / 越狱工具清单 143.5 / 银之钥 140.6）。
- 所以**任何单一平底都必然牺牲一半**；「中调最稳」的直觉是错的——中调上总有一个素材刚好撞色。
- **按 minimax 判据，白底是全场最优**：没有任何素材掉到 86/255 以下；暗底最差只有 0.8（精心磨制的小刀 在白底 180.0）。
- 唯一的反向项：**暗素材在白底上对比最高**（骑士盔甲 194.5），**暗底会吃掉暗素材**（骑士盔甲 1.2）。货架实拍也证实：A 行里「骑士盔甲」几乎糊进卡身。

产出：`白底可行性判定.png`（10 素材 × 白/暗/骨 三种底，2.5x）。

## 三、白底真正的代价：和货架拉不开

货架真身（`components/card_area.tscn` 读出来）：

- `TrayPaper` = `paper_tile.png` 平铺，expand_mode=1 / stretch_mode=1
- `ShelfEdge` = 2px 边框 `(115,85,37)`
- `RailRule` x102~104 / `DockRule` x1638~1640，铜色 @ α0.325

## 三、⚠️ 暴露四个冲突（不解决就不能实装，必须你拍板）

1. **本作「槽位」其实没实现。**
   `characters.json` 虽然写成 `{"jewelry": "…"}`，但代码 `_equipment_names()` **只取 `.values()`，把 key 丢掉了**；
   `Player.player_equipment` 是无序 **Array**。代码里**没有任何地方按 class 限定槽位、也没有「每类一件」的约束**。
   → 要落地苏丹式槽位，**得新增两件事**：① 用 `class` 反查槽位 ② 「每槽一件」的约束（或明确不做约束、只做展示）。

2. **一件装备可以属于多个 class。**
   例：`精心磨制的小刀` = `["weapon","jewelry","tool"]`（法拉叶剧情给的）。
   苏丹是「一件装备一个槽」，本作不是。**三个选项**：
   ① 多槽都显示（同一图标出现 2-3 次，**信息最真**）｜② 只进 `class` 数组里第一个命中的槽（与 `category_minor()` 口径一致）｜③ 多 class 装备单列一个「通用」槽。
   → **我默认按 ① 渲染**（图中的小刀就是会同时在武器/饰品/工具三格出现），你要 ②③ 就说。

3. **class 字段里混着非装备。**
   同一字段还有 `book`（书）/`clue`（线索）/`good`（商品）/`""`（空）。
   → 槽位集合必须走**显式白名单** `{weapon, armor, jewelry, tool}`，不能「把所有 class 都当槽」。

4. **不是每件装备都有 `icon`。**
   `年少的欢喜` **没有 icon 字段**；`goods.json` 5 件都有。
   → 已做降级：无 icon 时画**名字首字**（大字、淡色），**不留白方块**。
