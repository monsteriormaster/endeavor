## 1. ✅ 多骰判定的执行键恒灰（会卡死主线）—— 已修

**位置**：`components/trigger_popup.gd:1061-1071`

```gdscript
if resolver == "" and not (check_v is Dictionary):
    return _required_slots_missing(display)
if resolver == "":          # ← 这一行只可能被 multi 分支走到
    return true
```

`_is_execute_disabled()` 只有两个调用点：无 `check` 的 display（`_update_text` 980 行）和 `mode=multi*` 的 display（993 行）。前一类的 `check_v` 不是字典，走第一行就返回了；能落到第二行的**只剩 multi**。于是所有「多骰判定 + 触发器没有 resolver」的档，不论槽位填没填满，执行键一律禁用。

**动态验证**（`debug/_multi_exec_probe.gd`，headless 实跑，`MULTI_RESULT total=6 bad=6 resolver_caused=6`）：把必填槽全部填满后仍禁用 6 条，只在内存里把 `_expanded["resolver"]` 换成一个占位串，6 条全部放行。说明拦的就是这一行。

**受影响的 6 条档**：

| 触发器 | 阶段 | 档 | 玩家后果 |
|---|---|---|---|
| 群死凶器的调查 | t2_阶段二 | 推进 | 丹尼斯主线卡在阶段二 |
| 群死凶器的调查 | t3_阶段三 | 收网 | 同上 |
| 群死常规的处理的调查 | t2_阶段二 | 试探 | 同上 |
| 调查丹尼斯 | t2_结算 | 夜探·潜入 | 只能失败收场 |
| 夜间调查剧院 | t1_潜入 | 万事俱备 | 这条线另外四档全是 `lock_execute: true`，等于整条废掉 |
| 涂鸦大作战 | t1_再战 | 放露易丝 | 该分支不可用（还有兜底档，不算死） |

**建议改法**：整段化简成两句——`lock_execute` 命中就禁，否则只看必填槽。多骰的成败本来就是 `_compute_v` 的 multi 分支在算（1252 行起），拦按钮没有道理。

```gdscript
func _is_execute_disabled(display: Dictionary) -> bool:
	if _has_lock_tags(display):
		return true
	return _required_slots_missing(display)
```

改完复跑 `res://debug/_multi_exec_probe.tscn`，`bad` 应为 0。

## 2. ✅ 每次换场景必刷一组 SCRIPT ERROR —— 已修

**位置**：`components/scene_spot.gd:1238-1239`（`_show_panel`）

```
ERROR: Parameter "data.tree" is null.
SCRIPT ERROR: Invalid access to property or key 'process_frame' on a base object of type 'null instance'.
   at: _show_panel (res://components/scene_spot.gd:1239)
```

复现路径：鼠标移到地图图标上（面板浮出，进 `_show_panel(true)` 的两个 `await`）→ 点下去换场景 → 图标随旧场景 `queue_free`，节点已离开树但协程还挂在第一个 `await` 上 → 醒来后 `get_tree()` 是 null。一次巡游 14 次换场，14 组红字，一次不漏。

玩家这一侧没有可见症状（不崩、不卡），但协程半路死掉，面板状态会残留；日志里真正的错误被这 14 条刷掉。

**建议改法**：第一个 `await` 之后补一句 `is_inside_tree()` 检查。

```gdscript
	await get_tree().process_frame
	if not is_inside_tree():
		return
	await get_tree().process_frame
	if seq != _panel_seq or not container.visible:
		return
```

确定键灰，文案「如果来这里不是学习可是会被赶出去的」。玩家本来就是学生，却被当成来捣乱的。

**改法两步**：

### 7.6 过场 `_busy` 硬丢弃（对应 §6 建议项）

`script/scene_transition.gd` 三处改动：

1. **排队一次**：`change_scene` / `flip_cover` 撞上 `_busy` 不再直接 `return`，而是把这次请求存进
   `_queued_change`（只留最后一次，不排长队），`_finish()` 末尾 `call_deferred()` 补跑。
2. **抓帧令牌**：每次抓帧前 `_capture_token += 1` 并留 `my_token`，醒来后先比对令牌 ——
   过场被别的路径收尾 / 被看门狗放弃，就不会拿一张过期的快照把人盖掉。
3. **看门狗**：`_capture(token)` 起一个 `CAPTURE_TIMEOUT = 2.0s` 的一次性 timer，超时就把令牌记进
   `_aborted_token` 并 `_finish()` —— `await RenderingServer.frame_post_draw` 万一永远等不到，
   `_busy` 也不会永久卡死（这是「点地图完全没反应」的兜底）。
